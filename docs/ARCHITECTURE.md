# 重构架构说明（第一轮验证）

## 当前目标

本提交只验证一个闭环：

`云门总图 → 弟子居 → 偏舍 → 返回弟子居 → 返回云门`

核心要求：

1. 进入下一层后，上一级地点完全退出视图。
2. 每一层都是独立“地图页”，不是把一级、二级、动作同时平铺。
3. 返回入口不得放在长列表末尾，也不得依赖滚动到底才能看见。
4. 有 parent 的页面，返回按钮固定在页面顶部地图栏；根层隐藏。
5. 页面主体自行滚动，并为手机宿主底栏预留空间，最后一个地点不能被外层导航遮挡。

## 为什么改返回按钮位置

Muse/宿主环境的底部导航可能以覆盖层形式存在，它不会可靠反映到 `env(safe-area-inset-bottom)`。

因此：

- **禁止**把关键返回操作放在页面底部。
- **禁止**让返回按钮跟随地点长列表一起滚动。
- 返回按钮属于地图导航，固定在当前地图顶部。
- 主体列表单独滚动，并额外预留宿主底栏 clearance。

## 目录职责

- `src/core/`：状态、路由、存档、时间、事件等跨系统核心能力。
- `src/world/`：地点树、NPC 日程、遭遇等世界数据。
- `src/ui/`：纯 UI 渲染与交互层。
- `assets/`：从原单文件 HTML 中逐步拆出的图片、音频与样式资源。
- `adult/`：只保留公开的接口说明；私人成人内容不进入仓库。

## 第一轮验收标准

- 云门点击弟子居：云门地点全部退出。
- 弟子居点击偏舍：弟子居地点全部退出。
- 弟子居顶部始终可见“返回”，点击回云门。
- 偏舍顶部始终可见“返回”，点击回弟子居。
- 手机端无需滚到底寻找返回按钮。
- 最后一项地点/动作可以滚动到宿主底栏上方，不被遮挡。
- 返回后不残留下一级地点。

## 下一步（仅在闭环验证通过后）

1. 从原 HTML 迁移现有视觉框架和非成人素材。
2. 抽出时间系统（年 / 月 / 时辰）。
3. 迁移城镇、后山、演武场等多层地点。
4. 再迁移修炼、功法、战斗、NPC 日程和存档。
